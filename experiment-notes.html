DVD-R 与 DVD-RW 的三盘实验

← 返回主指南

以下实验在 2026 年 10 月 5 日完成，使用同一台外置 ASUS BW-16D1HT 3.10 机芯和 Windows。记录的是这组介质、软件及写入模式的结果，供理解 Live UDF、会话导入和可擦写盘的区别；其他设备需要重新验证。每次写入后都正常弹出、重插，再读取文件并比较 SHA-256。

盘片 软件与布局 写入、重插后的结果 未验证或停止位置
A：空白 DVD-R Windows Live File System，UDF 2.01 新建文件、记事本保存同名新版、复制同名文件的替换和新增另一文件均能重插读回；已记录扇区逐次增加 未测试删除；结果不保证其他编辑器也能直接保存
B：空白 DVD-R CDBurnerXP 4.5.8.7128，UDF 1.50，8×，允许以后追加 第一批两份文件刻录、软件校验和重插后的 SHA-256 均通过 清空临时项目后执行“导入区段”，待刻录项目仍为 0 个文件，因此没有写第二批，也没有测试封盘
C：DVD-RW Windows UDF 2.01，restricted overwrite 写入 v1、由 Windows 文件 API 写成 v2、删除测试文件、快速擦除并重新初始化后写入新文件；每一步均重插核验 直接改写使用文件 API，不应表述成“记事本保存成功”；快速擦除不是安全抹除

盘 B 最能说明“能看见旧盘”与“已导入旧目录”的区别。CDBurnerXP 上方浏览区域仍能打开第一批文件，下方待刻录项目却为空。继续写一个新会话可能让旧文件在当前目录里消失，所以实验停在写入前。这不能推出 CDBurnerXP 在所有版本和所有 UDF 布局下都不能续写。

另有一张先后由不同软件写入的 DVD-R，在 Windows Live 下能追加新文件，重插后也能读回；但对旧文件执行一次同名写入，读出的文本却是旧内容与新内容拼接。命令返回成功不足以证明内容按预期替换。续写前应把“新增文件”“覆盖同名文件”“编辑器保存”分别测试。

DVD-R 上多次保存后，光驱可能显示一个已完成的记录会话以及一个为下次写入预留的空白会话。此时 State of Last Session: Empty 或 Incomplete 不能单独证明此前写入失败。应同时看会话与轨道信息，并以重插后的文件和哈希为准。

实验只说明写入当时能读回，不预测多年后的保存寿命。用于归档时，还要保留第二份副本并定期复查。
